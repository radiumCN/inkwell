# 0.6.0-beta.1 性能改进落实

日期：2026-11-16。本轮基于 `0.6.0-performance-review.md`，不包含漫画、TTS，也没有改动分页坐标或翻页动画算法。

## 已落实

| 项目 | 改动 | 行为保护 |
| --- | --- | --- |
| 搜索排序 | 字数正则只编译一次；字数、日期值按不可变 SearchHit 懒缓存；生产排序函数可独立验证 | 合并新增来源会生成新实例，旧发布快照不变；保留中文次级排序、缺失值与稳定排序 |
| 导入查重 | SQL 在数据库内筛选同名同作者的本地书，不再逐本加载全书库实体 | 用与 Kotlin 完全一致的 Unicode 空白字符修剪；保留移出书架、占位补文件与本地/网络类型区分 |
| 统计榜单 | 一次观察 id/标题/作者/隐藏状态轻量投影，在内存选前五；消除逐本查询 | 隐藏书时长仍计总数；墓碑书仍可显示历史名称；隐藏状态变化会刷新榜单 |
| RSS 规则 | 按 id 与规则内容/转换版本复用解析结果，管理列表与时间线共享缓存 | 启停独立覆盖；内容变化失效；坏规则也缓存；LRU 最多 64 条且原文合计不超过 100 万字符，超限回退重解 |
| 字体 IO | 初次扫描移至 IO，扫描发布串行化；导入达到 64MB 上限即中断复制 | 可用性检查读取实际字体文件，不误用异步列表初值；保留校验、原子命名与失败清理 |
| 冗余清理 | 删除复核列出的 8 处无调用接口/属性；动画倍率改用 primitive float state | 保留仍在用的 AppTabContent、JS 桥、历史迁移和基准夹具；同步调整开发规范中的旧入口说明 |

## 验证与边界

- 查重回归在真实 bundled SQLite 上执行生产查询，检查中文全角空格、制表符、NBSP 等边界；另核对整张 Char 范围的空白字符定义。
- 搜索测试验证原比较器与新排序的结果一致，并检查新增来源后的数值失效和旧快照保留。
- 字体测试使用持续产生数据的输入流，验证超过上限时最多读取额外一个判定字节，不读取完整大文件；支持空流和恰好达到边界。
- RSS 测试覆盖内容和转换版本失效、启停/分组复用、损坏规则、LRU 淘汰与超大规则不入缓存。
- 导入 SQL 当前仍可能扫描书表，没有新增规范化键列或索引；本轮消除的是整库实体反复传出和构造的成本，不宣称查找复杂度已变成 O(1)。统计轻量投影仍随书表变化重新查询，但无关字段没有变化时由 distinctUntilChanged 阻止后续重算。
- 缓存上限以内可复用 RSS 转换；超过容量的条目可能重新解析，不宣称任意数量订阅都能全部常驻。

生产排序复测入口：`docs/performance/ProductionSortProbe.java`。它直接运行本轮实际 `orderSearchHits`，包含中文 Collator 次级比较，并以重复解析比较器作基线；基线也使用本轮预编译正则。结果只适用于开发机 JVM，不换算手机帧率。

当前没有连接真机，实际冷启动、帧率、耗电与覆盖安装仍需设备验收。

## 最终验证结果

命令：`JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew :core:test :reader:testDebugUnitTest :app:testDebugUnitTest assembleDebug :app:assembleRelease :app:lintDebug :baselineprofile:compileNonMinifiedReleaseKotlin --offline`。

全部通过：单测 1059 项（core 555、reader 85、app 419），失败、错误、跳过均为 0。debug/release 包构建、基准模块编译和 Lint 通过；Lint 从 25 条降至 23 条 warning，没有 error，余下主要为依赖提示、接口约定和先前已核查的 Context 警告。`git diff --check` 通过。

### 实际排序函数的 JVM 复测

在 Gradle 构建结束后执行，JDK 21、2000 本书、每本 3 个来源；六轮预热、九轮中位数。每种排序先比较输出列表，保持原顺序和中文次级比较结果一致。

| 排序 | 比较器重复解析基线 | 新实例首次排序 | 同实例后续排序 |
| --- | --- | --- | --- |
| 字数 | 100.404 ms | 8.730 ms | 1.598 ms |
| 更新日期 | 143.041 ms | 7.930 ms | 1.928 ms |

基线也使用本轮预编译正则，因此主要对照的是缓存排序值的收益。这个探针调用实际生产排序，但输入仍为合成数据，没有包括网络、UI、手机处理器与真机掉帧；不能据此宣称完整搜索快了相同倍数。原始记录为 `docs/performance/production-sort-results.txt`，不与开发前不同口径的 SortProbe 数字直接比较。

### 资源裁剪

release 已开启 `isShrinkResources`。两份本地构建中，APK 由 9336702 字节变为 9013883 字节（约 9.34 → 9.01 MB），压缩后的资源部分由 820549 变为 505556 字节，少 314993 字节；res 文件条目由 432 减到 362。AAPT2 检查前后 20 套 mipmap 启动图标均在资源表中。

总包体对比包含本轮收尾的常量整理，资源部分另行统计；没有把包体减少解释为运行时帧率提升。明细见 `docs/performance/release-size-comparison.json`。构建使用本机配置的签名流程，未推送发布。

安装包：`app/build/outputs/apk/debug/app-debug.apk` 与 `app/build/outputs/apk/release/app-release.apk`。当前版本仍为尚未发布的 `0.6.0-beta.1`；本轮未另行打 tag，也未修改数据库版本（仍为 v22）。
