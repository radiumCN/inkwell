# 书源搜索性能基线

固定夹具验证 8 路并发下的调度行为。以下数字用 Kotlin 协程的虚拟时钟测得，不含 Android 界面布局、真实 DNS、网络传输或解析。

| 夹具 | 首条命中，改前 → 改后 | 整轮，改前 → 改后 | 命中 | 超时 | 发送请求 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 16 个健康源 | 400 → 400 ms | 2,900 → 2,900 ms | 16 → 16 | 0 → 0 | 16 → 16 |
| 32 个混合弱网源 | 10,650 → 2,400 ms | 17,150 → 16,900 ms | 16 → 16 | 8 → 8 | 32 → 24 |

弱网夹具包含 8 个卡住的过期快源、8 个仍在限流冷却期的源，以及 16 个能返回结果的源。改后先给这些仍能响应的源分配槽位，冷却中的源留待下次搜索。过期快源不占首批优先位置，但继续用较短的旧超时作为首次尝试的参考；实际超时后再放宽。并发上限保持 8。

运行固定基准：

```powershell
.\gradlew.bat :app:testDebugUnitTest --tests 'com.radium.inkwell.ui.search.SearchNetworkBenchmarkTest' --offline
```

真机对比使用同一部手机、同一份书源导出和相同关键词，分别测冷启动与连续搜索。在正常网和固定延迟、限速配置下各重复至少 10 次。对比 `search.first_visible.duration_ms`、`search.round.end.duration_ms`、超时率和已完成源数，同时单列 `prepare_ms`。搜索词分别覆盖精确书名、作者和无命中；提前结束的轮次与完整轮次分开统计。
